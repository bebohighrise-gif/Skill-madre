# Attributions

This project uses general evidence-first engineering patterns and the open Agent Skills file convention. It contains no provider SDK, model integration, account credential, proprietary runtime, or vendor-specific installer.

The reverse-engineering guidance is limited to authorized targets, preserves evidence and uncertainty, and does not include third-party source code or binaries.

The research-derived methods reference summarizes publicly documented patterns from skill specifications, coding-agent workflows, rule systems, and structured delivery toolkits. It intentionally uses independent wording and does not copy source code, prompts, documentation prose, templates, branding, or proprietary assets. Source-specific licenses, trademarks, adoption claims, and host behaviors remain separate from Madre's MIT license and must be reviewed before reusing any external material.

The community-derived methods reference summarizes method-level patterns observed in highly visible public GitHub repositories covering interface design, engineering, agent coordination, catalogs, specification, automation, and security. Stars and forks were used only as dated discovery signals. No source code, prompts, expressive documentation, exact schemas, names, logos, screenshots, or third-party assets were copied; each external repository and dependency keeps its own license and attribution requirements.

The 0.7.0 references independently synthesize public methods from agent-skill and coding workflow projects; image and video documentation; OWASP, NIST, PortSwigger and digital-investigation guidance; and the public REA project. No third-party skill pack, implementation, prompt, expressive text, media, or branding was imported. Source URLs and scope notes are included in each reference. The REA repository states that REA-authored code is MIT-licensed, while third-party material retains separate licenses; this does not transfer rights to Madre or make REA a dependency. Standards, platform guidance, tools, licensing, and host behavior must be rechecked at use time. Repository activity and popularity are discovery context, not evidence of efficacy or safety.
