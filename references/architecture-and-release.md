# Architecture and release decisions

Load this module for broad structural changes, competing designs, packaging, deployment, or rollout.

For a material architecture decision, record constraints, alternatives, trade-offs, security, accessibility, performance, operations, migration, reversibility, and objective revisit triggers. Prefer the least complex option that satisfies established constraints.

For a release, establish exact source revision, artifact identity, target environment, configuration source, rollout mechanism, health checks, permissions, compatibility, signing assumptions, and rollback criteria. Do not deploy, publish, tag, or alter production without required authorization. A local build does not prove deployment or production health. If live verification is unavailable, label the result as a release candidate.
